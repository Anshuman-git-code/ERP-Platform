## Key Mental Models (read these after you finish all 45 files)

**Why this construction order matters:**
- `schema.prisma` → generates `@prisma/client` types → everything else imports those types
- `errorHandler.ts` → defines `AppError` → `auth.ts` imports it → routes import `auth.ts`
- `app.ts` → imports all routes → `index.ts` imports `app`
- `setup.ts` → overrides `DATABASE_URL` → every test file imports `setup` first

**The one rule the entire codebase is built on:**
Stock integrity requires database-level row locking (`SELECT FOR UPDATE`), not
application-level checks. Every operation that touches `physicalQty` or
`reservedQty` uses `prisma.$transaction` with raw SQL locking. This is why the
tests include concurrency scenarios — to prove the locks actually work.

**The five mandatory business rules and exactly where each is enforced:**

| Rule | File | Mechanism |
|---|---|---|
| Cannot reserve more than available | `routes/orders.ts` PATCH `/:id/confirm` | `SELECT … FOR UPDATE ORDER BY id` inside `$transaction` |
| Cannot dispatch more than available | `routes/transfers.ts` PATCH `/:id/dispatch` | `SELECT … FOR UPDATE` on source rows |
| Destination only increases on receipt | `routes/transfers.ts` both endpoints | Dispatch touches only source; receive touches only destination |
| Transfer cannot be received twice | `routes/transfers.ts` PATCH `/:id/receive` | `SELECT … FOR UPDATE` on the transfer row itself + status check |
| Unauthorized user blocked | `middleware/auth.ts` | `authenticate()` + `authorize(...roles)` on every route |
